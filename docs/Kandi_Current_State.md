# Kandi Current State

Reconstructed 2026-09-05. Engineering evidence through 2026-08-20; later professional discussion through 2026-09-04.

Kandi is Owen’s solo ECE project: a festival friend-finding wearable that exchanges GNSS coordinates over a **915 MHz LoRa mesh**, computes direction relative to wrist heading, and points with an LED ring. It works without cellular service, Wi-Fi, or internet during use. The intended product is screenless and kandi-styled; the current oversized prototype has an OLED for debugging. Preserve both the useful-product ambition and the learning/portfolio goal.

**Current goal and next order:** finish a wearable CAD enclosure for the existing hardware, print/fit it, and reshoot the demo while worn. Then implement and **measure** adaptive power savings. Then build a simple two-layer LED ring PCB as a fabrication exercise. A full custom RF PCB comes later. **ESP32-S3 versus nRF52840 is open**, to be decided with power measurements. Owen explicitly changed the order to CAD first on August 18 and did not want another relay field run soon. The old “before school / two weeks” target is historical.

**Architecture:** three LilyGo T-Beam Supreme boards, ESP32-S3FN8 + SX1262 + MAX-M10S GNSS + QMI8658 IMU + QMC6310N magnetometer + SH1106 OLED + AXP2101 PMU + 18650 battery; external 16-pixel WS2812 ring on IO2/DI, 3V3/GND. Eight logical sectors drive pairs of pixels. Hardware-free Python in `CoreLogic/` supplies the reference behavior; C++ Arduino/PlatformIO in `Firmware/` implements drivers and ports. Exact Python filenames include `Led_Logic.py` and `tilt_compensation.py`, despite different aliases in the docs.

**Completed according to the records:** peripheral bring-up; distance/bearing and tilt-compensated heading; per-board NVS hard-iron calibration; mesh serialization/dedup/timed relay; eight-slot roster; sticky selectable navigation target; LED freshness and arrival states; 635 m residential direct-link observation; three-node relaying with 628 m endpoint separation; walk-in arrival behavior; demo footage captured. Historical boot tests total 42: 19 core and 23 mesh. A separate 26-case synthetic compass test is not part of that count. No fresh hardware test was performed during migration, and footage publication is unconfirmed.

**Implemented protocol and controls:** `KNDN` is a 19-byte little-endian packet. Keep origin `senderId` unchanged through relays; update only `txNode` and decrement the hop limit. Group ID is a plaintext placeholder. Seen cache: 32 slots/30-second expiry. Relay queue: eight slots. SNR-weighted delay: 200–2,000 ms, weak first; duplicates cancel pending relays. New beacons: hop limit 3, every 10 ±2 seconds. Short button press <600 ms cycles target; long ≥600 ms toggles roster. Arrival-flash press cancels without triggering another action. Target >30 seconds old is stale, >120 seconds lost; fallback to a living member is automatic. Arrival is <10 m, flashes eight seconds, re-arms after >15 m. Navigation blink half-periods are 150/400/800 ms at <50/<200/≥200 m.

**Before any future flash:** the inspected source has `MESH_MODE=1`, `MESH_DEVICE_ID=3`, `MESH_GROUP_ID=1`, `MESH_BLOCKED_SENDERS={1}`. These are board-specific forced-test settings, not a generic build for all units. Distinguish transmitter from originator when applying a blocklist. Antenna must be attached before any transmission. Keep PMU initialization first; GPS needs both ALDO4 and IO7 HIGH. Mag is I²C 0x3C and OLED 0x3D, sharing pins 17/18; PMU uses the other bus on 42/41. Avoid reintroducing the slow u8g2 path; the adopted raw SH1106 driver is documented in the technical snapshot.
